# 场地补全独立验收

验收日期：2026-10-30。范围是本次场地语义、规则填充、渲染与净空，不评价建筑模型，也不将程序化景观称为北京实景测绘。

## 证据口径

对照采用 `evidence-landscape/views.json` 中固定的相机、视野、种子和光照。旧版为 v0.4.2，新版为 v0.5.0。评分直接依据漫画中景、庭院近景和正上方三组对应截图；彩色总览作为全局补充。

实景参考为[北京日报 2024-10-23 报道](https://news.bjd.com.cn/2024/10/23/10944711.shtml)中北京 CBD 管委会提供的绿地广场照片，存档截图见 `evidence-landscape/references/cbd-plaza-aerial.png`。照片可支持“宽铺装、低矮草坪、交错路径和边缘疏树”的形态选择，但其拍摄时间、相机和覆盖区域都与当前模型不同。没有逐地块配准，不从这张图计算真实还原率。

## 代码审查与修复记录

独立审查发现并交由主代理修复了两项问题：

1. 长椅长轴原先横跨示意入口，中心距通道边仅 0.05 米，长 2 米的座椅会侵入通道约 0.95 米。已改为沿通道纵向布置并校验占地；验收应以长椅完整矩形和通道净空为准，而不能仅检测中心点。
2. 水体经 bbox 裁切后返回闭合环，Three.js 三角剖分会删除重复闭合端点。旧 helper 在删除之前拼接顶点，导致有孔洞时索引错位。合成测试中应为 1,500 平方米的水面被画成 2,050 平方米，并覆盖孔洞。主代理已将顶点拼接移至三角剖分之后；水洞面积与范围测试通过。

画面审查还确认了球场上的灰色碎斑。主代理将标线嵌入支撑面，消除叠面，并让细白线与宿主共享物体身份，避免细线被额外描出双重黑边。最终近景中的球场已恢复连续底色和细白标线；静态截图不能证明所有距离和连续运动完全无闪烁。

另一项已反馈的设计问题是大建筑优先耗尽树木与座椅预算，后面的住宅、绿带和大空地难以获得装饰。新版改为按模板和场地轮换选择候选，保留预算并分散到不同地块。

已审阅的通用约束包括：多边形孔洞、OSM 用途优先、道路与建筑退距、已知水体排除、铁路/工业上下文保护、相同种子稳定，以及经平移/旋转后的非北京合成场景。所有候选仍属示意，入口的真实门位与产权边界未测绘。

## 定量检查

`unfilledBeforeFraction` / `unfilledAfterFraction` 是约 12 米采样间距的地面覆盖诊断，且道路退距区计入已占地。它不是逐像素空白率、精确土地面积或真实绿化率。生成耗时是本机 CPU 构建耗时，不是 GPU 帧率。

独立检查结果保存在 `evidence-landscape/review-checks.json`。最终规划 604 处场地：340 处庭院、108 处高楼前场、128 处退界绿带、28 处大空隙景观。模板树候选 600 棵，按四类分配为 244 / 112 / 122 / 122 棵，统一净空后实际接受 591 棵；场景总树数为 2,692。

全部推断树的中心与水体、停车、运动、工地、广场、裸地相交数为 0；与地面步行路径及其 1 米余量的相交数也为 0。该检查没有覆盖树冠整体体积。规划器的异常几何跳过计数为 0。已加载新增 OSM 用途后，规则补全前后的未建模地面采样比例为 46.54% → 25.71%；这不是旧版到新版全部改动的精确面积差。
