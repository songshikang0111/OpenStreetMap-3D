# 空地景观引擎：证据、规则与换区方法

本轮处理建筑与街道之间的裸底色。数据边界来自 OSM；在数据缺失的地方生成可关闭的景观示意。没有按北京坐标逐块硬编码，也没有从照片分割地物或恢复真实设计图。

## 参考证据

- [北京日报 2024-10-23，CBD 管委会供图](https://news.bjd.com.cn/2024/10/23/10944711.shtml)：实际打开并查看鸟瞰与地面照片。中央长草坪由步道分割，两侧乔灌木形成层次，建筑前保留宽铺装。照片中的树阵、草坪、硬地关系用于选择模板，不作为测绘边界。截图见 `evidence-landscape/references/cbd-plaza-aerial.png`。
- [北京市建筑设计研究院，中信大厦项目](https://www.biad.com.cn/project/id/58/)：项目位置及其南侧公共绿地关系。用于确认区域语境，没有复制其建筑或景观模型。
- [OSM 数据审计](landscape-osm-audit.md)：原抓取遗漏了部分标签和关系；原解析还遗漏了 4 个 `highway=pedestrian + area=yes` 广场。扩展同一 bbox 查询，按 `type:id` 去重新增 48 个对象，保留原始 tags、几何和来源信息。

照片日期与 OSM 快照日期不同；地图上的施工地可能已经变化。本轮保留明确的 OSM 用途，不能据美观需要直接把施工地覆盖成公园。

## 需求与实现

| 需求 | 引擎能力 | 验收依据 |
|---|---|---|
| 恢复有数据却没画的场地 | 识别草地、树林、花坛、公园、广场、停车、运动、施工与裸地；建筑停车楼和地下场地不压到地面 | 标签测试、真实快照测试、OSM审计 |
| 补建筑到街道的空白 | 沿建筑外墙与道路推导前场、庭院和绿带，布尔裁切到可用空间 | 固定机位前后图、占地冲突测试 |
| 补较大的残余空隙 | 用距离采样寻找宽敞空地；生成倒角边界、宽步道与不对称草坪 | 大空地 fixture；采样仅选中心，不渲染网格 |
| 留出空间而非堆满树 | 铺装、低灌木、草坪、疏树和座椅分层；草坪保持开敞，树林才较密 | 近景、俯视；共享树冠 LOD 与数量预算 |
| 已知用途优先 | 所有明确场地都排除推断；水、建筑、道路、台阶及工业/铁路背景区保守避让 | 多边形差集、孔洞、道路和树木净空测试 |
| 漫画也能读出场地 | 地面材质使用宽尺度灰度，低灌木有高度；保留铺装留白 | 漫画中景及彩色同机位 |
| 换区可复用 | 无地名/经纬度特判；种子稳定、参数 JSON、模板预算和关闭开关 | 平移旋转 fixture、开关与视角链接测试 |

已知停车场和运动场会获得裁切到自身边界内的示意标线；边界来自 OSM，内部车位和运动线是程序规则，不代表真实场地测量或标准尺寸。

## 数据与生成顺序

1. 加载基础 OSM、街道补充、场地补充；重复的 `type:id` 不追加。
2. 解析 multipolygon 外环与内洞；地表物理用途与商业/住宅用地语境分开。`commercial` 并不意味着整块铺草。
3. 计算连续道路、桥梯占地；构建建筑退界、道路边带、水岸及明确地物排除索引。
4. 优先输出已知 OSM 场地。剩余空间按建筑边、道路边和大空隙生成模板，互相去重，保留通路和边带。
5. 模板树经过街道系统的二次净空、树间距和桥梯检查；所有树共用现有实例化与 LOD。座椅完整矩形占地必须位于铺装内。
6. 合并场地网格与材质；漫画区分草坪、灌木和纸白铺装。

入口走廊是几何预留，不是实际门位识别，也不证明所有真实建筑入口都已连通。现阶段没有高程场、屋顶花园、遥感分类、产权或消防设计能力。

## 用鸟瞰图适配另一地区

先换 OSM bbox 和两个补充快照，再编辑 `public/data/landscape-profile.json`，无需修改规划器。抓取器支持参数见 `python scripts/fetch_landscape_details.py --help`。

| 参数 | 含义与调整方向 |
|---|---|
| `frontDepth` / `maxFrontDepth` | 建筑周边模板深度；密集旧城降低，宽退界园区提高 |
| `buildingSetback` / `accessWidth` | 建筑维护边和示意主通道宽度 |
| `plantingInset` / `forecourtApron` / `gardenApron` | 草坪缩进与楼前铺装；增加可提高硬地比例 |
| `vergeDepth` / `shrubWidth` | 路侧绿带与低灌木边带宽度 |
| `treeSpacing` | 模板树间距；树少且开敞的地区增大 |
| `commonMinRadius` / `commonMaxRadius` | 接受的大空隙尺度，避免用大公园模板填小缝 |
| `maxCommons` / `maxSites` / `maxTrees` / `maxProps` / `maxSurfaces` | 数量预算；不会因扩大地图无上限增加 |

照片校准是人工判断硬地与绿化比例、树列节奏和庭院尺度。若需要某一块的真实精确形状，应补 OSM 或另加带来源的矢量边界，不能只调随机种子获得“真实还原”。

关闭「空地景观补全」会保留已知 OSM 地表，只移除本轮推断模板、模板树、座椅和内部示意标线。已有版本的行道树等规则细节仍由相应开关控制。状态随视角链接保存；恢复相同种子可复现。

## 验收与限制

`node scripts/audit_landscape.mjs` 输出 CPU 构建用时、模板计数、面积与约 12 米间隔的未覆盖采样估计。采样把道路净空带也视作已有空间，因此不是像素级空白率或测绘面积。剩余空地不会被强制全部种满。

完整图证、指标和独立评分见 [本轮报告](evidence-landscape/report.html) 与 [独立验收](landscape-validation.md)。静态截图不能证明所有移动过程无闪烁，也没有 GPU 帧率基准。

几何布尔运算使用 MIT 许可的 [polygon-clipping](https://github.com/mfogel/polygon-clipping)，处理交集/差集与内洞；OSM 数据继续遵循 ODbL。
