## 分工与工作区

所有产品工作沿用原五个子对话和 worktree。A/B/C/D 从干净工作区在修复基线新建 `codex/phase1-<组件>-repair` 分支，保留原组件分支；E 沿用集成分支。不得重置、丢弃或混入无关改动。

| 任务 | 修复责任 | 主要所有权 |
| --- | --- | --- |
| A 核心 | 降低低/中 LOD 几何和分块绘制成本，保留完整覆盖、地标轮廓、身份与接缝，支持默认预算 | `src/core/` 的编译/LOD/编解码实现及其测试；核心相关生成器按需调整 |
| B 数据/CLI | 标准下载的可靠路径、端点配置、自托管能力、真实下载/缓存/构建证据 | `src/data/`、CLI 数据/任务入口、项目 source 配置、local-server 数据/任务接口及其测试 |
| C 风格/导出 | 项目外部风格模块声明、验证、本地打包及标准静态站点恢复，失败不能虚报成功 | 风格契约、独立打包模块、`src/cli/export.js`、`studio/static-viewer.js`、外部风格教程与其测试 |
| D SDK/运行时 | 修复固定镜头 LOD/请求抖动、独立 draw/triangle 预算策略、保留合法 AO 参数 | `src/runtime/`、`src/sdk/` 与对应测试；配合 A 达成默认预算 |
| E 工作台/集成 | 工作台接通数据端点与项目外部风格，集成 A–D，修复交叉问题、组织最终产品基准 | Studio、打包与文档、跨组件接线、集成证据；整合后统一改共享接口文件 |

`ProjectConfig` 类型和 Schema 的 source/style 字段会分别被 B/C 涉及，保持字段级修改，E 负责合并并核验；A/D 避免无关接口格式化。B 所有本地服务主文件先由 B 改，C 通过独立 helper/模块提供风格能力及接线说明，E 在合并 B/C 后接通 Studio 路由。SDK 的 AO 修复仅由 D 修改，C 只验证风格参数管线与契约。

E 与主对话共享集成 worktree：E 开发/集成期间主对话不编辑产品文件或并行提交；E 报告冻结提交后，主对话开始最终独立验收。其他任务不得直接写 E 的 worktree。各角色可以自行启动独立只读审查 subagent，不能把自己的实现报告当作独立通过。

## 不变的验收要求

- 不提高默认 600,000 整帧 triangles、1,200 draws 等预算，不删除压力案例、缩小指定测试覆盖或隐藏必要地物来通过。
- 保留主体几何真实 LOD、全部对象身份/来源、地标分组、道路水域接缝。降低成本优先简化/合批/分配细节，不能用纹理变淡冒充几何优化。
- 固定镜头两个已知机位各至少15秒真实浏览器复验，记录 LOD、近景成本、取消与同 URL 请求数；不能只看最终 settled 或高端 GPU 帧率。
- 整合后的同一真实提交运行北京/京都 fixed 1/4/16 与 grow 1/4/9 共12组，每组至少60秒；按整帧累计真实绘制/GPU，保留冷启动、加载、完整逐帧统计及每组5次资源往返。测量串行进行，避免多个任务同时压测 GPU。
- 正式 CLI/工作台在明确小范围真实获取数据，记录实际端点、来源、时间、哈希，验证缓存及构建。不能把 fixture、仓库旧快照或导入改名为成功 live 下载。不无限重试或规避公共服务限流。
- 外部风格须有明确项目入口/依赖/资产契约；标准 `export web` 产物在非根路径、拒绝外网时独立加载，四官方+外部风格正确，参数保存/恢复一致。无效入口发布前明确失败并保留旧站点。
- 公共接口修改同步类型、Schema、help、教程与证据；每次实质修复都测试并提交。
- 主对话独立复跑 tests/types/build/package，复验真实 CLI/工作台/外部风格和参数，核对最新性能 raw；发现问题返回对应模块继续修复，直到 AC01–AC27 无必需 fail/not-run。
