# 二期性能摘要

2026-11-26 在本机 Ryzen 7 7840S / Radeon 780M、Linux、Chrome 158、1280 × 720、DPR 1、balanced 实测。Android 和 iPhone 均未验证。一期 RTX 4090 的结果只覆盖一期场景包。

| 里程碑 | 使用的实测方法与结果 |
| --- | --- |
| M0 工具链 | 一期格式化前后 201 个 JS/TS 文件的转换结果一致。此阶段未引入瓦片渲染。见 [A 报告](A/report.md)。 |
| M1 瓦片 | 最新同机对照中，167 块 L1 的 Node p95 为 111.4 → 95.5 ms（目标 60 ms），京都 6 块独立 Chrome Worker 的 p95 为 248 → 182 ms（目标 120 ms）。两版使用同一份瓦片。详见 [C8](C8/report.md)，较早的一组测量见 [C5](C5/report.md)。 |
| M2 运行时 | 启用整组预算后，同一城区 60 秒路线的三角形峰值由 617,754 降至 569,063，驻留估算由 225,212,516 B 降至 134,214,476 B。3,578 帧均保留可见瓦片。见 [D3 受控对照](D3/report.md)。 |
| M3 整城 | 恩克赫伊曾完整市界 1,016 块瓦片，735.91 秒，峰值 RSS 937,732 KiB。城区路径使用 272 块的独立样本。构建吞吐、内存、恢复和缝隙抽查见 [F 报告](F/report.md)。 |
| M4 风格 | 五次切换保持几何对象身份，新增网络请求 0。见 [D2 实测](D2/report.md)。 |
| M5 本机漫游 | 集成版城区漫游 601 秒、35,868 帧，首个可用画面 1,149 ms、首屏 782,537 B、空白帧和瓦片错误均为 0。帧间隔 p95 16.8 ms，每分钟长帧 2.00 次。Worker p95 159.2 ms，上传峰值 16.5 ms，1 帧超出 128 MiB 预算。补计首次加载的源字节后，同路径 60 秒共 3,531 帧，驻留估算均在预算内。见 [I 基准报告](I/report.md)。 |

基线为本轮开发期间的本机测量，同时有其他构建任务。报告逐份记录 SDK 提交和数据哈希。驻留字节为运行时估算，逐帧日志按 I 报告的命令写入仓库外。

后续拾取元数据复验覆盖五城 81,735 条要素记录。带顶点归属的多要素网格改为一次扫描；城区固定路径的上传峰值仍超过 4 ms，见 [D4 对照](D4/report.md)。
