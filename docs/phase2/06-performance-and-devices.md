# 06 性能与设备

由 WP-D 在开发中自测，由 WP-I 独立验收。

## 1. 原则

沿用一期的证据口径，二期不放松：

- 帧率结论只来自真实浏览器的整帧统计。Node 耗时、无 NaN 检查、截图评分都不是性能证据。
- 多通道渲染的绘制调用和三角形数按整帧累计。
- 估算的驻留字节不是实测显存，报告中必须注明。
- 达不到目标时如实标记未通过，不得删除压力样本或改变统计口径。
- 未实测的设备和平台标记为"未验证"，对外文档不得声称支持。

## 2. 设备基线

| 档位 | 参考设备 | 状态 |
| --- | --- | --- |
| 桌面高端 | 一期的 RTX 4090 / Chrome | 已有，仅作上限参考，不作为达标依据 |
| 桌面主流 | 集成显卡笔记本（近四年的主流核显）/ Chrome | 本轮按 D5 使用本机 Ryzen 7 7840S / Radeon 780M 与 Chrome 158，结果见 [I 报告](evidence/I/report.md) |
| 移动主流 | 一台中端 Android 手机 / Chrome，以及一台近四年的 iPhone / Safari | 两种手机均未验证，见 D5 |

在用户提供真实设备之前，WP-D 可以用桌面浏览器的 CPU 降速和降低分辨率做开发期的粗略自检，但这类结果只能标记为"模拟"，不能用于验收。

## 3. 运行时目标

测试条件：预构建的整城瓦片集，固定的 60 秒相机路径（包含远景俯瞰、街道近景、快速平移、快速缩放、往返），预热后测量。

| 指标 | 桌面主流 | 移动主流 |
| --- | --- | --- |
| 帧间隔第 95 百分位 | ≤ 16.7 ms | ≤ 33.3 ms |
| 超过 50 ms 的长帧 | 每分钟不超过 3 次 | 每分钟不超过 6 次 |
| 首个可用画面（从导航开始，本地网络） | ≤ 1.5 s | ≤ 3 s |
| 单块 L1 瓦片 Worker 解码加生成，第 95 百分位 | ≤ 120 ms | ≤ 500 ms |
| 主线程单帧上传时间片 | ≤ 4 ms | ≤ 6 ms |
| 估算驻留字节上限 | 256 MB | 128 MB |
| 设备像素比上限 | 2 | 2，且总像素不超过 250 万 |
| 资源往返 | 往返 20 次后驻留字节不持续增长 | 同左 |
| 页面稳定性 | 10 分钟连续漫游不崩溃 | 10 分钟连续漫游不崩溃、不被系统回收 |

三档质量的默认预算：

| 预算项 | `low` | `balanced` | `high` |
| --- | --- | --- | --- |
| 可见三角形 | 250,000 | 600,000 | 1,500,000 |
| 绘制调用 | 600 | 1,200 | 2,400 |
| 驻留字节 | 96 MB | 128 MB | 256 MB |
| 近景细节数量 | 4,000 | 18,000 | 40,000 |
| 阴影 | 关 | 开，低分辨率 | 开 |
| 像素比上限 | 1.5 | 2 | 2 |

`balanced` 的数值沿用一期已验证的默认值。移动设备默认选 `low`，由运行时根据设备能力探测决定，开发者可覆盖。

绘制调用是城市尺度下最容易失控的指标。每块瓦片内的几何必须按材质角色合批，目标是每块 L1 瓦片不超过 12 次绘制调用（不含近景实例），L0 不超过 4 次。

## 5. 基准工具

在 `scripts/benchmark-integration/`（一期已有）的基础上扩展，放在 `scripts/benchmark-tiles/`：

- 固定路径回放：路径用经纬度相机关键帧描述，保存在 JSON 中，与具体瓦片集绑定。
- 采集：帧间隔分布、长帧、整帧绘制调用和三角形、驻留估算、取数字节、Worker 排队与耗时、上传时间片、GPU 计时（不可用时明确标注）。
- 输出：一份机器可读的摘要 JSON（小于 200 KB，可入库）和完整逐帧记录（不入库）。
- 报告必须记录：设备、CPU、GPU、浏览器及版本、视口、像素比、质量档、瓦片集名称与哈希、SDK 提交哈希。
- 提供一个可在手机上打开的基准页面，结果可以通过二维码或复制文本带回。

## 6. 持续回归

- CI 中运行不需要 GPU 的部分：瓦片体积预算、解码与生成的 Node 耗时、每瓦片三角形数与绘制调用数的静态统计、包体积。超过阈值时 CI 失败。
- 需要 GPU 的基准不放进默认 CI，由发布前的人工流程运行，结果摘要入库。
- 每个里程碑结束时更新一次性能摘要表（`docs/phase2/evidence/perf-summary.md`）。

## 7. 验收要点

对应 09 中的 AC901–AC908。

静态检查对每块瓦片先预热，再取三次 Node 解码与生成耗时的中位数，按样本分别报告 p95。解码上限使用 AC207 的 5 ms，单块色彩通道三角形数（含树）使用 balanced 的 600,000 上限。可传 `--max-generate-ms N` 在同一机器设置明确的生成耗时门槛。AC312 的 167 块代表样本与独立浏览器结果另见 [C5](evidence/C5/report.md)。
