# 09 工作包

每个工作包（WP）可以交给一个独立的开发 agent。执行规则见 [README 的 agent 须知](README.md)。

## 1. 总览与依赖

| 工作包 | 名称 | 里程碑 | 依赖 | 规格 |
| --- | --- | --- | --- | --- |
| WP-A | 地基：包结构、格式化、定位 | M0 | 无 | 01、07 |
| WP-B | 瓦片格式与编解码 | M1 | A | 02 |
| WP-C | 生成器抽取与小范围构建 | M1 | A、B | 01、03 |
| WP-D | 地图运行时内核 | M2 | B、C | 04、06 |
| WP-E | 拾取、要素状态与叠加层 | M2 | D | 04 |
| WP-F | PBF 输入与整城构建 | M3 | C | 03 |
| WP-H | MapLibre 图层 | M3 | D | 04 |
| WP-G | 风格契约与默认风格 | M4 | D | 05 |
| WP-I | 性能与设备验收 | M5 | D、F、G | 06 |
| WP-J | 发布：文档、demo、npm | M5 | 全部 | 07 |
| WP-K | 集成与独立验收 | 每个里程碑末 | 当期全部 | 全部 |

可并行的组合：B 与 C 的前半（生成器抽取）；D 完成后 E、H、G 并行；F 与 D 并行。

所有工作包共同的完成条件（不再逐个重复）：

- 一期全部测试（`npm test`）、类型检查（`npm run test:types`）和构建（`npm run build`）仍然通过。
- 新增代码有单元测试，新的公共接口有类型和至少一个可运行例子。
- 按 `AGENTS.md` 提交，交付报告写入 `docs/phase2/evidence/<编号>/report.md`。

## 2. WP-A 地基

**目标**：在不改变任何行为的前提下，为后续工作准备好结构和规范。

**写入范围**：根 `package.json` 与锁文件、`packages/*/package.json` 骨架、`tsconfig*.json`、格式化与检查配置、`.github/`、`.git-blame-ignore-revs`、`AGENTS.md`、`CONTRIBUTING.md`、`docs/phase2/naming.md`、`docs/phase2/competitors.md`；纯格式化提交可触及 `src/`、`studio/`、`test/`、`scripts/`、`bin/`。

**任务**：

- A1 建立 npm workspaces，创建 `tiles`、`generators`、`builder`、`map`、`styles-ink`、`details` 六个包的骨架（可构建、可测试、内容为空导出）。现有 `packages/styles`、`packages/landmarks` 纳入 workspaces。
- A2 配置 TypeScript 严格模式、格式化和静态检查，行宽 120。
- A3 对一期代码做一次纯格式化提交，并登记到 `.git-blame-ignore-revs`。
- A4 CI 增加：workspaces 的构建与测试、格式检查、包文件清单检查。
- A5 准备命名候选名单（07 第 2 节），写入 `docs/phase2/naming.md`，交用户决定（D1）。
- A6 联网核实 [00 第 1 节](00-vision-and-scope.md) 竞品表中各项目的现状（许可、最近更新、是否提供 SDK），更新该表并把依据写入 `docs/phase2/competitors.md`。
- A7 整理依赖：构建工具移到开发依赖，`three` 的版本范围声明清楚。
- A8 更新 `AGENTS.md` 和 `CONTRIBUTING.md` 的入口说明，指向二期文档和新包结构。
- A9 仓库瘦身的准备：列出可移出的文件清单和体积，等待 D3；在 D3 决定前不移动文件。

**验收**：

- AC104 格式检查在 CI 中生效，故意引入一处违规会使 CI 失败。

- AC107 竞品表每一行都有可点开的依据链接和核实日期；无法核实的项明确标注。
- AC108 根包的运行时依赖中不再包含构建工具和类型包；`npm pack --dry-run` 的文件清单与改动前相比没有意外增减。

## 3. WP-B 瓦片格式与编解码

**目标**：实现并冻结 [02](02-tile-format.md)。

**写入范围**：`packages/tiles/`、`schemas/tileset.schema.json`、`docs/phase2/02-tile-format.md` 的第 9 节、`docs/phase2/evidence/B/`。

**任务**：

- B1 墨卡托与瓦片数学：经纬度与瓦片互转、瓦片范围、每单位米数、瓦片局部米制与世界坐标的变换矩阵。
- B2 `tileset.json` 的类型、Schema 和校验。
- B3 容器、字符串表、要素层和网格层的编码与解码，含量化。
- B4 覆盖位图的读写。
- B5 度量：用手工构造的代表性数据（密集低层、高层 CBD、带立交的道路）测量体积和解码耗时，决定是否采用额外的网格压缩，并核对两级缩放的选择，结论记入 08。
- B6 第三方参考解码说明（写入 02 第 9 节）和一个不依赖本项目的最小解码脚本例子。
- B7 损坏输入的健壮性测试（截断、随机翻转字节、超大长度字段）。

**验收**：

- AC201 往返测试：随机生成的要素层和网格层，编码再解码后与输入相等（量化字段在量化网格上相等），用例不少于 1,000 组。
- AC202 量化误差不超过 5 cm；垂直范围和水平范围符合 02 第 5.2 节。
- AC203 相邻瓦片共享边界上的同一顶点，各自量化后换算回墨卡托坐标的差为 0。
- AC204 截断和损坏的输入全部返回结构化错误，没有未捕获异常、死循环或超过 1 秒的解码。
- AC205 未知层和未知次版本字段被跳过且不影响已知层；未知主版本被拒绝并给出明确诊断。
- AC206 `decodeTile` 可在浏览器 Worker 和 Node 中运行，包没有运行时依赖。
- AC207 单块代表性 L1 瓦片在 Node 中的解码耗时不超过 5 ms（记录机器配置）。
- AC208 独立审查 agent 仅凭 02 第 9 节的说明，不读 `packages/tiles` 源码，写出能读出建筑轮廓和高度的脚本。
- AC209 墨卡托数学的测试覆盖纬度 ±80°、缩放 0–20、经度 ±180° 边界。

## 4. WP-C 生成器抽取与小范围构建

**目标**：把一期建模代码按"规划/生成"分界拆开，并把一期的小范围数据构建成瓦片。

**写入范围**：`packages/generators/`、`packages/builder/`、`bin/city.js` 中的 `tiles` 命令入口、`src/cli/` 中新增的命令注册、被抽取的一期模块（保留转发导出）、`test/phase2-generators*`、`test/phase2-builder*`、`docs/phase2/evidence/C/`。

**任务**：

- C1 建筑：规划部分（高度与屋顶参数、分部归并、立面语法选择）进 `builder`，生成部分（墙体、屋顶、立面属性）进 `generators`。生成器输入为 02 的 `building` 要素。
- C2 树木：选址与避让进 `builder`，树形实例化进 `generators`。
- C3 水域、绿地、地表：合并与裁切进 `builder`，三角化进 `generators`。
- C4 道路：纵断面求解与路面布尔运算进 `builder`；桥梁、楼梯、护栏由带高程的中心线在 `generators` 中生成。达不到耗时预算的结构类型先用烘焙网格层，并在 08 记录。
- C5 地标：`builder` 调用现有配方与生成器，产物写烘焙网格层。
- C6 `massing` 档案的简化规则（02 第 2 节）。
- C7 管线阶段 `partition → plan → cut → encode → finalize`（03 第 3–5 节），输入为一期标准化 JSON。规划格和缓冲圈机制在此实现，供 WP-F 直接复用。
- C8 CLI：`city tiles build`（`--project`、`--bbox`、`--resume`、`--json`）、`validate`、`inspect`、`serve`。
- C9 构建报告与来源等级统计（03 第 6 节）。
- C10 一期场景包管线改为调用新的生成器（或保持旧路径并以对比测试证明两者输出一致），不得出现两套各自演化的建筑生成逻辑。

**验收**：

- AC301 一期全部样本（`public/data` 下的 12 份数据）都能构建成瓦片集并通过 `city tiles validate`。
- AC302 北京国贸和京都祇园 9 块范围的瓦片集总体积分别不超过 4 MB 和 12 MB（gzip 后）；单瓦片满足 02 第 6 节预算，超限的逐个列出原因。
- AC303 同一输入用单个规划格和不少于 4 个规划格分别构建，所有瓦片的内容哈希完全一致。
- AC304 同一输入、配置和版本重复构建两次，产物逐字节相同。
- AC305 对每个样本，瓦片中的建筑身份集合与一期场景包的 `featureIndex` 中的建筑集合相同；每个建筑只出现在一块瓦片中。
- AC306 由瓦片生成的建筑几何与一期直接生成的几何对比：每栋建筑的包围盒差不超过 10 cm，三角形数差不超过 2%（差异逐类说明）。
- AC307 道路、水域、地表在瓦片边界处无缝：在 20 个随机边界点两侧采样，位置差为 0，高程差不超过 1 cm。
- AC308 同一瓦片在 Node 与浏览器 Worker 中生成的几何，顶点数与三角形数相同，坐标差不超过 1 mm。
- AC309 构建在任一阶段被终止后用 `--resume` 恢复，结果与未中断的构建逐字节相同（不少于 5 次随机终止）。
- AC310 构建报告含各类对象数量、三种来源等级占比、不完整关系数、降级与回退清单；`--json` 输出符合一期 CLI 约定。
- AC311 生成器包不引用 DOM、WebGL 或渲染器；在不含 DOM 的 Worker 环境测试中通过。
- AC312 单块 L1 瓦片的生成耗时（Node，记录机器配置）：代表性样本的第 95 百分位不超过 60 ms；超过的对象类型列出并说明处理方式。

## 5. WP-D 地图运行时内核

**目标**：实现 `createMap` 及其相机、瓦片选择、流式加载和 Worker 管线。

**写入范围**：`packages/map/`（不含 `overlays/` 与 `maplibre/` 子目录）、`src/runtime/` 中被抽取的模块（保留转发导出）、`apps/demo/` 的最小页面、`scripts/benchmark-tiles/`、`test/phase2-map*`、`docs/phase2/evidence/D/`。

**任务**：

- D1 把一期 `src/runtime` 的预算、策略、资源回收、统计、GPU 计时抽成两种模式共用的内核；`createCityViewer` 行为不变。
- D2 相机：经纬度、缩放、俯仰、方位的模型，`jumpTo`、`easeTo`、`flyTo`、`fitBounds`，鼠标与触屏交互，惯性。
- D3 坐标换算与浮动原点：`project`、`unproject`、`lngLatToWorld`、`worldToLngLat`、`createAnchor`。
- D4 瓦片选择：屏幕空间误差、覆盖位图、预算降级、替换规则与迟滞。
- D5 加载管线：可取消的取数、Worker 池、解码与生成、可转移缓冲、分时上传、失败重试。
- D6 临时默认风格：在 WP-G 完成前，用一期的 `color` 风格绑定瓦片场景，保证有可看的画面。
- D7 事件、`whenIdle`、`getStats`、诊断、署名控件、`dispose`。
- D8 `apps/demo` 最小页面：加载本地瓦片集，显示相机参数和统计。
- D9 基准页面与固定路径回放（06 第 5 节）。
- D10 单文件 ESM 构建与包体积检查。

**验收**：

- AC401 04 第 2 节的最小用法在 `apps/demo` 中原样可运行，显示北京国贸样本。
- AC402 04 第 3 节的全部接口存在且类型与文档一致；例子纳入类型检查。
- AC403 `project` 与 `unproject` 互逆：地面上随机 1,000 个点往返误差不超过 0.5 像素。
- AC404 与 MapLibre 的相机一致性：缩放 13–19、俯仰 0–75°、方位随机的 200 组参数下，同一经纬度地面点的屏幕位置差不超过 2 像素。
- AC405 浮动原点：沿直线连续平移 60 km，过程中没有可见跳变（相邻帧同一地面点的屏幕位移连续），`createAnchor` 创建的对象保持在正确的经纬度上。
- AC406 替换规则：在缩放级别 14 与 17 之间往返的固定路径上，逐帧检查没有任何时刻出现"某区域既无父瓦片也无完整子瓦片"的空洞。
- AC407 相机静止时请求数为零；镜头微动（小于 1 米的抖动）不触发瓦片切换。
- AC408 相机快速移走后，未完成的过期请求被取消，Worker 队列不超过预算上限。
- AC409 主线程不做解码和几何生成：性能记录中这两类函数只出现在 Worker 线程。
- AC410 加载失败的瓦片在重试耗尽后发出 `tileerror`，画面保留父级覆盖；覆盖位图标明不存在的瓦片不产生请求。
- AC411 往返 20 次后估算驻留字节不持续增长；`dispose` 后 Three.js 的几何、纹理、程序计数归零，Worker 全部终止。
- AC412 触屏交互在真实移动浏览器上可用：单指平移、双指缩放、双指旋转、双指俯仰（未实测的平台标记未验证）。
- AC413 一期 `test/phase1-runtime*` 与 `test/phase1-e2e*` 全部通过。
- AC414 `@scope/map` 压缩后不超过 180 KB（不含 `three`），单文件 ESM 构建可通过 `<script type="module">` 直接使用。
- AC415 桌面高端参考设备上，北京与京都样本的固定路径满足 06 第 3 节的桌面目标（主流设备的验收归 WP-I）。
