# 二期开发计划书：开源 3D 城市底图层

日期：2026-11-12。状态：二期实施基线。规划基线为 main 的 `d2d5d5b`（一期 AC01–AC27 已通过）。

本目录是一组规格文档。每份文档描述一个子系统的目标、契约和验收标准；`09-work-packages.md` 把它们拆成可以直接分配给开发 agent 的工作包。文中的新命令、接口和目录是待实现的交付契约，不代表当前版本已经支持。

实作和验收进度见[路线图](../../ROADMAP.md)、[本机性能摘要](evidence/perf-summary.md)和[各里程碑集成记录](evidence/K/report.md)。

## 一句话定位

把 OSM 变成好看的 3D 城市（建筑、道路、桥梁、绿化），开源、可嵌入、可自己改风格。它既是一个普通的 Three.js 场景，也能作为 3D 图层叠在 MapLibre 上。

## 里程碑总览

| 里程碑 | 交付 | 完成标志 |
| --- | --- | --- |
| M0 地基 | 包结构、代码格式化、定位文档、风格与核心解耦的边界 | 一期 344 项测试仍全部通过，新包骨架可构建 |
| M1 瓦片 | 瓦片格式、编解码、几何生成器抽取、小范围 → 瓦片 | 现有北京/京都样本构建成瓦片，体积达到预算 |
| M2 地图运行时 | `createMap`、经纬度相机、流式加载、Worker 生成、拾取、标记 | 本地 demo 可在预构建样本上按经纬度漫游并加标记 |
| M3 整城 | PBF 输入、分格规划、整城构建、单文件归档、MapLibre 图层 | 一条命令构建一个完整城市并可连续漫游 |
| M4 风格 | 声明式样式、三套默认风格、漫画风独立成包、真实性过滤 | 不改核心即可用配置文件换肤 |
| M5 发布 | 移动端性能达标、npm 包、在线 demo、英文文档 | 新用户五分钟内在自己的页面看到真实城市 |

M1 与 M0 之后的部分工作可并行，依赖关系见 [09](09-work-packages.md) 的依赖图。

## 执行 agent 须知

1. 先读 `AGENTS.md`、本文、00、01、08，再读自己工作包涉及的规格。
2. 每个工作包在独立的 Git worktree 和分支上开发，分支名 `phase2/<工作包编号>-<简述>`，不在 main 上直接开发。
3. 只写自己工作包"写入范围"内的文件。需要改别人的范围时，在交付报告里写明原因和改动，由集成工作包合并。
4. 规格与现实冲突时，不要悄悄偏离：先在 [08](08-risks-and-decisions.md) 的决策记录追加一条（问题、选择、理由、影响），再实现。涉及"待用户决定"清单的事项必须停下来问用户。
5. 验收以 09 中的 AC 编号为准。每个 AC 都要有可复跑的命令或脚本，以及原始输出摘要。
6. 证据写入 `docs/phase2/evidence/<工作包编号>/`，只放文本和小于 200 KB 的 JSON 摘要。截图、逐帧记录、生成的瓦片一律不进主仓库（原因见 07 的仓库瘦身）。
7. 以下动作必须得到用户明确同意后才能做：`npm publish`、推送远端、部署公开网站、改写 Git 历史、注册任何外部账号。
8. 性能结论只能来自真实浏览器的整帧统计。Node 耗时、无 NaN 检查、截图评分都不能当作 GPU 性能或真实性证明。未实测的设备和平台必须标记"未验证"。
9. 一期的公共接口（`createCityViewer`、`compileScene`、场景包清单、CLI 命令）在二期保持可用，直到 09 明确安排的迁移任务完成。

## 交付报告格式

每个工作包完成时，在 `docs/phase2/evidence/<工作包编号>/report.md` 写：

- 完成的 AC 及各自的验证命令和结果摘要。
- 未完成或未通过的 AC，以及原因。
- 提交哈希列表。
- 对冻结契约的任何偏离，及对应的决策记录编号。
- 已知限制和未验证的平台。
