# 03 构建管线

由 WP-C（小范围 → 瓦片）和 WP-F（PBF 整城）实现。输出格式见 [02](02-tile-format.md)，规划与生成的分界见 [01 第 2 节](01-architecture.md)。

## 1. 目标

- 一条命令把 OSM 数据构建成可静态托管的瓦片集。
- 输入既可以是一期的小范围 JSON，也可以是城市级 PBF。
- 结果确定：相同输入、配置和版本得到逐字节相同的瓦片。
- 可中断恢复、可增量重建、内存和耗时可预期。
- 不依赖浏览器或 GPU。

## 2. 输入

| 输入 | 阶段 | 说明 |
| --- | --- | --- |
| 一期标准化 JSON（Overpass / OSM Map / 项目 JSON） | M1 | 复用 `src/data` 的规范化，范围沿用一期上限 |
| `.osm.pbf` 文件 | M3 | 城市或地区级提取文件。用户自行下载，工具不自动下载大文件 |
| 构建范围 | M1 | 经纬度矩形，或 GeoJSON 多边形文件；PBF 输入时可省略，默认取文件范围 |

PBF 读取要求：

- 流式两遍读取：第一遍收集需要的路径、关系及其引用的节点 ID；第二遍取节点坐标。不得把整个文件解析成对象驻留内存。
- 节点坐标存放在类型化数组或磁盘临时文件中。
- 只保留本项目用到的要素类型（建筑及分部、道路、水域、绿地、树、相关关系），过滤规则集中在一个文件中，便于贡献者扩展。
- 读取库的选择由 WP-F 评估后决定，标准为：仍在维护、支持流式、许可与 MIT 兼容、能处理 500 MB 的文件。也允许自行实现解码。结果记入 08。
- 支持规模（二期承诺）：输入 PBF 不超过 1 GB，构建范围不超过 5,000 km²，峰值内存不超过 8 GB。超出时明确拒绝并提示先用外部工具裁剪，文档给出裁剪命令示例。
- 不得宣称支持未实测的规模。

## 3. 阶段

~~~text
ingest → partition → plan → cut → encode → finalize
~~~

| 阶段 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `ingest` | PBF 或 JSON | 过滤后的要素存储 | 记录来源文件哈希、时间戳 |
| `partition` | 要素存储、构建范围 | 规划格列表及各自的要素索引 | 规划格为缩放 12 的瓦片（北纬 40° 约 7.5 km） |
| `plan` | 一个规划格加缓冲圈 | 该格内的规划要素 | 可并行；见第 4 节 |
| `cut` | 规划要素 | 每块瓦片的要素集合 | 归属与裁切；见第 5 节 |
| `encode` | 瓦片要素集合 | `.c3t` 文件 | 同时生成 L0 和 L1 |
| `finalize` | 全部瓦片 | `tileset.json`、覆盖位图、构建报告 | 可选打包为单文件归档 |

每个阶段的产物写入构建目录下的缓存，带输入哈希。阶段完成后写完成标记；中断后重跑时跳过已完成且哈希未变的部分。

## 4. 分格规划

一期是全区域一次性规划，二期必须按规划格独立进行，同时保证结果与划分无关。

### 4.1 缓冲圈

每个规划格读取自身范围外扩一圈的要素（默认 800 m），用于：

- 完整取得跨界的建筑、关系和水域。
- 树木避让和场地规划所需的邻域。
- 道路纵断面的约束传播。

缓冲圈内的对象只参与计算，输出时只保留归属本格的对象。

### 4.2 与划分无关的规则

| 内容 | 规则 |
| --- | --- |
| 对象归属 | 建筑、地标整组、树木归属其锚点所在的瓦片。锚点由对象自身几何确定（例如外环顶点中 ID 最小的节点），不依赖处理顺序 |
| 随机性 | 一律由"来源对象 ID + 规则版本 + 项目种子"派生，或由量化后的世界位置派生 |
| 道路纵断面 | 把互相有高差约束的道路划为"坡度组"（例如一组立交）。每个坡度组整体求解，归属其最小 ID 成员所在的规划格。缓冲圈不足以包含整个组时，按需扩大读取范围，而不是截断 |
| 水域合并 | 按关系和相接多边形分组后整体合并，再按瓦片裁切 |
| 过大的组 | 坡度组或水域组的范围超过 20 km 时报 `GROUP_TOO_LARGE` 诊断，并回退为不做跨界求解的简化结果，同时保留诊断，不得静默 |

### 4.3 验证方式

对同一份输入分别用"单个规划格"和"多个规划格"两种划分构建，比较所有瓦片的内容哈希，必须完全一致（AC303）。这是二期最重要的正确性测试，沿用一期"固定范围 1/4/16 块"实验的思路。

## 5. 归属与裁切

| 对象 | 处理 |
| --- | --- |
| 建筑、建筑分部 | 整体归属一块瓦片，不裁切。分部跟随所属建筑 |
| 地标 | 整组归属一块瓦片，写入烘焙网格层 |
| 树、点状对象 | 归属所在瓦片 |
| 道路中心线、结构 | 在瓦片边界处切断，切点坐标和高程由共享规则计算，切点不是新的 OSM 节点 |
| 路面、水域、绿地、地表 | 按瓦片边界裁切多边形，使用统一的精度网格，避免相邻瓦片出现缝隙或重叠 |

桥梁、楼梯等结构若在边界被切断，两侧必须能各自独立生成并在边界处对齐。无法做到的结构类型整体归属一块瓦片。

## 6. 推断与真实性

- 高度、屋顶、树种等推断规则沿用一期（`src/osm.js` 的 `heightInfo`、`src/roofs.js`、`src/vegetation-rules.js`）。
- 每个推断属性写入来源等级（见 [00 第 5 节](00-vision-and-scope.md)）。
- 构建选项及默认值：

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `inferHeights` | 开 | 关闭后无高度信息的建筑使用固定的单层高度并标记为 `inferred` |
| `inferRoofs` | 关 | 沿用一期默认 |
| `ruleTrees` | 开 | 沿道路和绿地按规则补种树木，标记为 `inferred` |
| `landscape` | 关 | 场地补全，由 `details` 包提供 |
| `landmarks` | 开 | 命中官方配方时使用地标生成器 |

- 构建报告必须统计：各类对象数量、各属性三种来源等级的占比、不完整关系数量、被降级或回退的对象清单。

## 7. 命令行

在一期 CLI（`bin/city.js`）上新增 `tiles` 命令组，保持一期的输出约定：`--json` 时结果写标准输出、进度写标准错误，含 `schemaVersion`、`status`、`artifacts`、`diagnostics`，退出码确定。

~~~sh
# 从 PBF 构建整城
city tiles build --input beijing.osm.pbf --output ./out/beijing --json

# 只构建一个范围（西,南,东,北）
city tiles build --input region.osm.pbf --bbox 116.30,39.85,116.50,39.98 --output ./out/cbd

# 从一期项目的数据构建
city tiles build --project ./work/my-city --output ./work/my-city/tiles

# 恢复中断的构建
city tiles build --input beijing.osm.pbf --output ./out/beijing --resume

# 检查产物
city tiles validate ./out/beijing --json
city tiles inspect ./out/beijing --tile 16/53958/24829 --json

# 打包为单文件归档（M3）
city tiles pack ./out/beijing --output beijing.archive

# 本地预览
city tiles serve ./out/beijing --port 4181
~~~

选项：`--concurrency N`（默认为 CPU 核数减一，至少 1）、`--seed`、`--config file.json`（第 6 节的构建选项）、`--levels`、`--max-memory`。

`city tiles validate` 检查：元数据 Schema、每块瓦片可解码、覆盖位图与文件一致、体积预算、署名存在。`city tiles serve` 只绑定回环地址，支持范围请求和压缩，仅用于本地预览。

## 8. 构建性能目标

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 吞吐 | 8 核机器上不低于每分钟 20 km² 的密集城区 | 记录机器配置和实际输入 |
| 峰值内存 | 第 2 节规模内不超过 8 GB | 进程峰值常驻内存 |
| 增量 | 输入不变时重跑，耗时不超过全量的 5% | 第二次运行计时 |
| 恢复 | 在任一阶段被终止后恢复，结果与不中断的运行逐字节相同 | 随机终止测试 |

达不到目标时如实报告测得的数字，并在 08 记录，不得调整输入或统计口径来过关。

## 9. 预构建示例城市

为了让新用户不经过本地构建就能看到效果（见 [00 第 6 节](00-vision-and-scope.md)），维护一份示例构建清单 `examples/cities.json`，包含每个示例的输入来源、范围、构建配置和产物哈希。

- 初始清单使用一期已有的真实样本范围：北京国贸、上海陆家嘴、京都祇园、阿姆斯特丹运河区、曼哈顿金融区。
- 产物不进 Git。发布位置和方式由 07 规定。
- 清单必须能用一条脚本命令完整复现。
