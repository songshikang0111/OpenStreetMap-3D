# 00 定位与范围

## 1. 要解决的问题

开发者想在自己的应用里放一座真实的 3D 城市时，现有选择都有明显缺口：

| 现有产品 | 能做到 | 缺口 |
| --- | --- | --- |
| MapLibre + 开源矢量瓦片 | 全球 2D、文字标注、建筑拉伸、可自托管 | 3D 只有平顶盒子，没有屋顶、建筑分部、桥梁、树 |
| Cesium + OSM 建筑 | 全球、地形、测绘级精度 | 偏重，建筑同样是盒子，风格化弱 |
| Mapbox Standard | 有美感的 3D 风格、成熟的原生 SDK | 闭源收费，不能自托管 |
| Google 实景 3D 瓦片 | 照片级真实感 | 收费，不能改风格，不能离线，没有单栋语义 |
| Streets GL | 开源（MIT），效果最接近本项目 | 是一个网站应用，不是能嵌入的 SDK；2025-08 后无推送 |
| F4map | OSM 3D 效果好 | 闭源 |
| 让 coding agent 自己从 OSM 写 | 一个下午得到能看的 demo | 数据长尾、瓦片接缝、内存与 LOD、真机性能都要自己踩 |

本表已于 2026-11-12 由 WP-A 任务 A6 联网核实，依据、链接和未能核实的项见 [competitors.md](competitors.md)。对外引用前请重新核实日期。

## 2. 价值主张

同时满足以下四点的产品目前是空位：

1. **有美感的 3D**：建筑带屋顶和分部，道路有路缘和坡度，桥梁有厚度和桥墩，有树和绿地。
2. **开源**：代码 MIT，数据 ODbL，可自托管，无需密钥。
3. **是 SDK**：装一个包，几行代码嵌进自己的页面。
4. **可二次开发**：场景就是 Three.js 对象，每个对象有语义角色和 OSM 身份，风格可以用配置或代码整体替换。

相对于"让 agent 自己写"，本项目提供的是 agent 做不出来的三样东西：在很多城市真实数据上验证过的正确性、现成可加载的城市数据、在真机上测过的性能。

## 3. 目标用户

按优先级：

1. **Three.js / Web 3D 开发者**：做数字孪生、数据可视化、互动作品、仿真、建筑和规划周边环境，需要一座真实城市作为场景。这是首要用户，缺口最明显。
2. **地图应用开发者**：已经在用 MapLibre，想把盒子换成真实的 3D 建筑。通过 MapLibre 图层接入，是升级而不是迁移。
3. **移动端开发者**：通过 WebView 封装使用，限于展示型场景。二期只保证移动浏览器可用，原生封装后置。
4. **接入本项目的 coding agent**：类型、Schema、结构化诊断和最小例子要让 agent 一次接对。

## 4. 项目边界

### 4.1 维护者负责的（基建）

- OSM 解析：关系、建筑分部、高度与层数、屋顶标签、道路、水域、绿地、树。
- 3D 结构计算：建筑体块与屋顶、道路表面与纵断面、桥梁与楼梯、水域与地表。
- 瓦片格式、构建管线、可静态托管的产物。
- 运行时：流式加载、LOD、资源预算、相机、拾取、叠加层。
- 风格契约和三套朴素的默认风格。
- 性能和正确性的持续回归。

### 4.2 交给开发者的（上层）

- 具体视觉风格、后处理、品牌化配色。
- 业务数据叠加、交互逻辑、UI。
- 地标的精细还原（通过配方扩展）。
- 街道小品、车辆行人、场地补全等装饰性内容（作为可选包存在，不属于核心）。

### 4.3 明确不做

- 搜索、路线规划、实时路况、POI 更新等在线服务。
- 运营瓦片服务器、构建服务器或任何需要持续付费的后端。预构建的示例城市以静态文件形式发布，不构成服务承诺。
- 测绘级还原和照片级真实感。
- 国内合规底图（审图号、坐标偏移）。文档须明确提示：OSM 在中国大陆的建筑覆盖稀疏，在大陆上线的应用需要自行处理合规问题。
- 替代 MapLibre 的 2D 底图和文字标注能力。二期选择与它互操作。

### 4.4 后置到二期之后（M6）

文字标注引擎、DEM 地形、用外部数据集补充建筑高度、iOS/Android/React Native/Flutter 封装包、WebGPU 后端、Unity/Godot/Unreal 适配、在线插件市场。瓦片格式须为地形和外部高度来源预留字段，但二期不实现。

## 5. 真实与推断

"好看但不一定真实"是本项目的明确立场，必须对用户透明：

- 每个生成对象的关键属性都标注来源等级：`observed`（OSM 直接给出）、`derived`（由标签换算，例如层数乘层高）、`inferred`（规则估算或补全）。
- 开发者可以按来源等级过滤和区分显示，例如只显示有真实高度的建筑，或者把推断高度的建筑渲染成另一种颜色。
- 场地补全、屋顶推断等会改变观感的推断保持显式开关，默认值在 05 中规定。
- 所有对外文案不得使用"真实还原""测绘级"之类的表述。

## 6. 成功指标

二期完成（M5）时必须同时满足：

| 指标 | 目标 |
| --- | --- |
| 上手时间 | 新用户照着 README，从零到在自己的页面看到一座预构建真实城市不超过 5 分钟，全程不需要本地构建 |
| 自建城市 | 一条命令把一个城市级 PBF 构建成可静态托管的瓦片 |
| 覆盖尺度 | 至少一个完整城市（建成区不小于 500 km²）可连续漫游 |
| 瓦片体积 | 满足 02 第 6 节的预算 |
| 性能 | 满足 06 的桌面和移动端基线 |
| 可换肤 | 只改一个样式配置文件即可得到明显不同的外观，不改核心代码 |
| 可嵌入 | 同一份瓦片能在独立 Three.js 场景和 MapLibre 图层两种方式下加载 |
| 可贡献 | 外部贡献者按 CONTRIBUTING 能在 30 分钟内跑通测试并完成一个标注为入门的改动 |

发布后的观察指标（不是验收条件）：在线 demo 访问量、npm 下载量、外部 issue 和 PR 数量。若发布后 8 周内没有任何外部使用者的反馈，应回到 08 重新评估投入方向。

## 7. 与一期的关系

一期交付的是"本地城市生成工具链 + 小范围场景包 + 漫画风渲染"。二期不推翻它，而是换重心：

- 一期的解析、建模规则、确定性、分块归属、LOD 预算、资源回收和测试是二期的基础，全部保留。
- 一期的"场景包"（单项目、固定原点、上限 16 km²）继续存在，定位为"小范围高精度场景模式"，供工作台和定制项目使用。
- 二期新增"瓦片模式"作为主路径，面向任意范围。
- 一期的漫画、线稿等风格和地标配方降级为可选包，不再是默认体验的一部分。
