# 三地泛化验证 · v0.8.0

## 2026-11-03：修复悉尼完整码头路网的高差约束

已恢复最初失败的取景范围：南-33.8640、西151.2050、北-33.8545、东151.2180，约1.2×1.1公里。`?site=sydney` 现在加载 `sydney-circular-quay.json`，保留584个建筑体块、1,656个道路对象；之前的 `sydney-harbour.json` 小范围样本继续保留，供下节修正前后证据与测试复现。

原因定位到真实人行通道 `1302672460` 与 `1302672463` 的上下交叉，以及相邻短连接路。旧算法按 `(两路半宽之和 + 2m)/sin(交角) + 采样间距` 扩大整个净空约束区，误把旁边连接段/平台纳入约束。短路环上最多允许约3.04米的高差，却又被强制要求至少3.6米净空，构成每轮约0.558米的正循环，迭代抬高到120米后报错。这不是网络下载失败；此前收窄取景范围绕开了路环。

通用算法现在按两条道路实际宽度交叠区的投影确定范围，并保留夹住边界的相邻采样点，确保边缘插值仍受约束。没有修改悉尼道路标签、删除道路、放宽坡度限制、取消交叉净空或提高报错高度阈值。

验证结果：

- 用旧版本道路求解器重跑同一份完整数据，仍可复现原错误；修正后23轮收敛，最大道路高度14米，160处交叉约束均保留，0处被判为模糊并跳过。118处共享节点名义高差进入连续求解。
- 新增7条真实道路的最小回归样本，以及完整悉尼路网检查。独立条带相交/高度插值检查覆盖160处交叉、1,841个顶点，净空容差1毫米；每条非楼梯道路仍满足原坡度上限，共享节点没有断层。北京原有184处交叉的独立桥底净空验收保持通过。
- [138项测试通过](sydney-road-fix/tests.txt)、[生产构建通过](sydney-road-fix/build.txt)。[构建审计](sydney-road-fix/audit.json)记录旧版错误、新版高差统计及几何非有限值0；[浏览器检查](sydney-road-fix/browser-check.json)确认完整场景加载结束，浏览器当次错误/警告列表为空。

![完整悉尼范围恢复加载](sydney-road-fix/wide-color.jpg)

## 2026-11-03：屋顶、未知空地与海陆修正

本节记录后续修正；下文 v0.8.0 的原始结果和评分保留作历史证据。

### 查明的问题

- 束河868个、拜伯里148个体块均无 `roof:shape`、`roof:height`，大部分连建筑用途和层数也未提供。不能把原版的坡顶直接解释为这批 OSM 数据里的真实屋顶。悉尼126个体块有86个形状标签，其中84个为当前未支持的 `many`、`round`、`circular`、`spherical` 等复杂形状。
- 旧景观引擎把建筑/道路周边残余空间视为可设计场地，没有真实绿地的证据。之前截图中的海上花园还叠加了水域丢失。未做实地逐点标注，不能报告一个量化误召回率。
- 悉尼港 `relation/1252425` 已存在于小范围 Map API 返回值中，但207个成员不完整；旧解析器无法闭合外环而丢弃水面。小地图又只画绿地、道路和建筑，没有水层。它同时是数据完整性和2D显示遗漏，不能只改配色解决。

### 本轮行为

1. 按 `roof:shape` 生成双坡、四坡、四角锥顶、单坡；读取坡高、屋顶层数、坡角和朝向，保留总高、真实轮廓及内庭院。坡顶不再叠平屋顶盖板、女儿墙或设备。复杂轮廓采用平面包络近似，不是通用直骨架屋顶。圆顶、歌剧院贝壳等仍未实现。
2. 默认关闭未知空地补全，仅保留手动的“试验：补全未知空地”开关；OSM 已标注的场地照常显示。未删除行道树/已标注绿地内的程序种植，它们仍是规则示意。
3. 增加“推测低层坡屋顶”，默认关闭。开启时仅用于面积20–350平方米、总高不超过12.5米、轮廓较规则且无庭院/分部的小房屋，不覆盖已有屋顶标签；不改原始建筑高度和标签，点选时注明推测来源。当前预览为束河、拜伯里打开此开关，悉尼关闭。
4. Map API 下载补齐相关建筑/地表 multipolygon 的缺失成员，记录每个 `/relation/{id}/full.json` 的来源和时间；对仍不完整的关系明确计数并跳过，不编造闭合边。水域/绿地先裁到取景边界；重叠港湾水域合并，避免同平面闪烁。2D/3D/植被排除共用水域几何，2D 增加水蓝、林地、草地、硬地和真实树点的区分。

### 验证与剩余边界

[136项测试通过](ground-roofs/tests.txt)、[生产构建通过](ground-roofs/build.txt)。新增检查覆盖四类屋顶的凹轮廓/庭院、坡顶总高与设备移除、束河真实轮廓共线数值回归、悉尼两处海域为水/歌剧院及植物园为陆、重叠水域不重复计数、地表及推测树不进入水域，以及残缺关系不伪造水面。

仍需改进：低层高度估算、地区传统屋顶/立面语法、歌剧院曲面、DEM 地形。此次修复适用于有可补全水域关系的样本；没有水域面、仅有开放 `natural=coastline` 的海岸仍需独立的海岸多边形处理，不能宣称全球海洋均已支持。

依据：[OSM Simple 3D Buildings](https://wiki.openstreetmap.org/wiki/Simple_3D_Buildings)、[Map API 与 relation/full](https://wiki.openstreetmap.org/wiki/API_v0.6)、[海岸处理说明](https://osmdata.openstreetmap.de/processing/coastline.html)。本轮未复制原版几何、程序或材质。

结论：这套引擎可以直接加载不同地区的OSM，生成可交互的漫画和彩色城市；高层商务区的迁移效果较好。**历史低层街区的地方风貌尚未通过验证**：高度估算、屋顶、街屋立面仍带有商务区原型的偏好。现在适合批量生成可审阅的原型，不宜直接宣称批量高还原。

本轮没有为新城市添加地标生成器、手摆树木或修改材质参数。只添加地点选择、独立数据入口、通用机位，并修复一个阻断京都加载的几何异常。三地均使用种子1、太阳135°/45°及v0.7的同一组漫画/玻璃参数。新地点使用同一套默认景观配置；北京保留原有补充数据和地区配置，不向其他地区混入。

## 暴露出的边界

### 1. 少量高度估算也能破坏整个天际线

阿姆斯特丹已知高度/层数体块的高度中位数为15.7米，但最高7个体块都是估算值。最高者`w266695079`为83.6米，周围150米内97个已知高度体块的中位数为16.2米。共24个估算体块超过附近已知高度中位数的两倍（邻居不少于5个）。这是异常筛查信号，并非逐栋实测证据，详见[高度审计](amsterdam-height-audit.json)。

原因可在`heightInfo()`直接定位：缺失高度的`commercial/office`仍随机估算8–22层，适合部分商务区，却会在旧城生成突兀高楼。京都虽有密集建筑轮廓，只有149个体块有高度或层数；通用估算决定了绝大多数视觉结果，不能把轮廓完整误认为三维资料完整。

### 2. 屋顶与地方立面是几何能力缺口

当前普通建筑主要挤出为平顶；`roof:shape`只影响部分设备布置，尚未生成对应坡面或山墙。本样本上海有33个、京都6个、阿姆斯特丹82个体块带`roof:shape`，即使标签存在，也还未充分利用。

祇园具有传统町家街屋，[日本国家旅游局的地区介绍](https://www.japan.travel/en/spot/84/)可作为建筑类型依据。阿姆斯特丹的窄地块节奏、窗型与多类山墙是重要特征，见[UNESCO城市遗产图集](https://whc.unesco.org/en/urban-heritage-atlas/Amsterdam/)。本轮截图中这些特征没有被表达，不能只靠换颜色补足。未以这些网页照片恢复任何逐栋几何。

### 3. 复杂地面几何会暴露数值问题

京都场地`osm:w430590712`的63条停车标线切割原先报`Unable to complete output ring`，导致整个城市构建中止。修复会先尝试原精度，再以1毫米、必要时1厘米网格统一场地与标线，裁去越界装饰；仍失败时保留源地面并省略该组装饰，记录计数。

这个实际失败样本现在在1毫米重试时成功：场地覆盖差异小于0.25平方米，保留超过25平方米有效标线；京都最终1次精度重试，0条因最终失败而省略的标线。回归样本保存在`test/fixtures/kyoto-paint-inlay.json`，不是按坐标特判。

### 4. 密集城市需要分块与合批

| 样本 | 本机Node构建耗时示例 | Mesh对象 | 当前视角三角数约 |
|---|---:|---:|---:|
| 上海 | 11.0 s | 766 | 244万 |
| 京都 | 29.1 s | 4,508 | 142万 |
| 阿姆斯特丹 | 35.4 s | 1,992 | 86万 |

这是CPU生成审计，受机器与同时运行的任务影响，不是浏览器首屏基准，也不是GPU帧率。京都每栋建筑仍有独立网格，阿姆斯特丹复杂轮廓/地面运算也有成本。三地顶点均为有限值，但尚未逐一核验桥高、交通层级、碰撞和移动GPU表现。边缘建筑可能跨出取样边界，`outsidePlanarVertices`仅作为诊断计数，不等于内部破洞数量。

## 主观评分与下一步

以下为实现者对本轮截图的10分制自评，不是独立评审或实景还原率，没有做逐栋实景对照。

| 项目 | 上海 | 京都 | 阿姆斯特丹 |
|---|---:|---:|---:|
| 漫画/彩色渲染可读性 | 8 | 6.5 | 7 |
| 街区布局辨识 | 8 | 7 | 8 |
| 建筑类型与地方风貌 | 6.5 | 2.5 | 3.5 |
| 可直接作为成品的程度 | 6.5 | 3 | 4.5 |

建议的通用引擎改进顺序：

1. **邻域高度估算与置信度**：真实高度、层数优先；缺失时结合相邻已知体块、用途和占地，避免商业用途直接触发高层；稀疏数据区域显式降低置信度。
2. **屋顶和街屋形体**：读取坡屋顶、屋脊方向、屋顶高度与分部；提供山墙、狭长连排、低层商住、木构外廊等可组合语法，通过标签/地区参数选择，而非按坐标写建筑。
3. **低层细节预算**：小屋顶设备、窗框与描边按街区密度、屏幕尺寸共同控制，避免密排街屋变成设备和窗格的噪声。
4. **分块、缓存、合批**：把“能生成单块”推进到可稳定扩展；保留对象来源与点选ID，降低密集地区的构建时间和绘制批次。
