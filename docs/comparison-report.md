# 北京国贸：原版对照与改进验收

日期：2026-10-29。状态：**已完成截图 QA 与逐项评分**。

人工加权评分从 **31.0 → 64.8 / 100**。这不是图像相似度或实景还原率；原版在树冠、远景抗噪、立面丰富度及地形上仍有优势。详细结论与每项剩余差距在 `evidence/scores.json`，离线交互画册在 `evidence/report.html`。

## 核心发现

原版的真实感不只是 OSM 轮廓与楼高。公开客户端有地区规则和中国尊、央视的专门形体生成器；普通楼按类型和条件变化立面，近处有实体窗框、凹窗或阳台；道路与绿地受约束地补树和设施。漫画渲染还区分外形/内部线、固有色/光照/投影、树冠/玻璃。

彩色俯视图由场景矢量数据绘制。检查中没有发现卫星 RGB 影像参与建筑恢复的链路；不能进一步断言作者制作地标规则时从未人工参考照片。详细证据与定位锚点见 `research-evidence.md`。

## 比较边界

- 同一地段：WGS84 39.90950,116.46050，北京国贸 CBD。
- 原版近区 1 km、远景 2 km；本地数据约 2.0 × 1.8 km，快照、分部和数量口径不同。
- 原版截图是同区域、同类机位参考，没有完整相机外参，不属于像素配准。
- `matched-before/` 与 `after/` 对应编号才构成本地匹配机位前后对照。
- `before/` 是历史证据。若尚无匹配基线，报告明确标为“历史截图未配准”。
- 地图数据为 OSM；生成的门窗、设备、补植与设施不被标为实景恢复。

## 已运行的验证

20项测试通过，生产构建通过。11组相机与参数在本地旧/新版重放并核对；原版仍仅是同地段参考。PNG实际导出2400×1211并检查署名；GLB实际导出50,929,872字节，检查glTF 2.0头、长度、JSON和署名，未宣称外部建模软件导入已验收。构建有Three.js vendor包约546 kB的体积提示。

`matched-before` 使用v0.1几何/渲染模块与当前共同相机、UI；原始未修改版另存在 `before`。真实高度28个、层数换算267个、推测182个。2473棵树全部程序补植；85处过街线、29处信号有OSM标注依据，灯车人仍为推测。

## HTML 报告生成

```powershell
cd C:\myGit\beijing-city-ink
python scripts/build_comparison_report.py
```

默认输出：

`C:\Users\宋世康\Documents\Codex\2026-10-29\https-tools-oyasumi-gamedev-com-rokehan\outputs\comparison\report.html`

HTML 内置 CSS 与交互脚本，不需要在线库。图片使用相对路径，因此分享时应一起保留 `comparison/` 文件夹。生成器还写入 `report-manifest.json`，记录图片路径、大小、SHA-256 和冻结需求文件的 SHA-256。

目录约定：

```text
comparison/
  report.html
  report-manifest.json
  scores.json              # 可选，最终人工验收后填写
  original/                # 原版截图与 ui-controls.json
  before/                  # 初始历史截图
  matched-before/          # 与 after 同机位/编号的 v0.1
  after/                   # 最终 v0.2；iteration-* 不进入正式相册
```

机位按文件名前缀匹配：01 俯瞰、02 天际线、03 街道漫画、04 街道彩色、05 俯瞰彩色、06 顶视、07 中国尊、08 央视、09 立面、10 屋顶、11 路口。后缀可为 JPG、PNG、WebP。相同编号多个文件时，优先排序第一项；匹配基线优先使用 after 的完整文件名。

### 人工验收输入 scores.json

放在输出 `comparison/` 内；也可用 `--scores PATH` 指定。下列只是结构示例，分数保持 `null`，不能当作真实评分：

```json
{
  "status": "draft",
  "reviewed_at": null,
  "reviewer": "主验收者",
  "summary": "等待最终截图 QA。",
  "scores": [
    {
      "id": "R1",
      "before": null,
      "after": null,
      "result": "等待检查中国尊和央视形体。",
      "remaining": "等待记录剩余差距。",
      "evidence": []
    }
  ],
  "checks": [],
  "commits": []
}
```

最终验收完成后设置 `status: "reviewed"`，填写每个 R1–R7 的真实 `before/after` 分数、`result`、`remaining` 和相对证据路径，例如 `after/07-citic-ink.jpg`。未标记 reviewed/final/accepted 时，报告不显示最终数值。只有七项前后分数都完整时才计算总分。

检查记录格式为 `{"name":"npm test","status":"passed","detail":"实际测试结果"}`；失败用 failed，其他状态显示待验证。提交记录格式为 `{"hash":"实际短哈希","requirement":"R4 / R5","detail":"该提交的改动"}`。不要填写未运行的检查或尚不存在的提交。

## 当前明确保留的差距

完整地形、全球流式数据、全部地区建筑语法、夜景和完整漫画特效不在本轮完成范围。地标是程序化形体近似；原版的相机和数据与本地并不完全相同。截图评分只说明此次样本中的视觉接近度。
